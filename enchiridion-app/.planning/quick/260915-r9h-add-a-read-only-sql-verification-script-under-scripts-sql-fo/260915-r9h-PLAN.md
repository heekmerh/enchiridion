For 004, check public.processed_payments, transaction_id primary key, cascading user_id foreign key to auth.users, idx_processed_payments_user, enabled RLS, its own-user SELECT policy and no INSERT/UPDATE/DELETE/ALL policy; check public.user_book_access RLS and its SELECT policy require caller user_id, granted, and null-or-future expires_at with no write policy. These digests come from migrations 002 and 003, respectively. Also label the corresponding body checks by their required logic: availability uses NOT EXISTS on profiles with case-folded names and blank-name exclusion; leaderboard sums daily_study_stats.performance_points with profiles, ranks users, marks user_id=auth.uid(), and includes the caller's row even outside result_limit. A signature-compatible stub must fail. Emit migration ID, check name, passed boolean, expected-condition diagnostic, and an overall pass/fail row. Add a header with the Supabase SQL Editor or psql -X -v ON_ERROR_STOP=1 -f scripts/sql/verify_001_004.sql execution path using an existing operator connection.
