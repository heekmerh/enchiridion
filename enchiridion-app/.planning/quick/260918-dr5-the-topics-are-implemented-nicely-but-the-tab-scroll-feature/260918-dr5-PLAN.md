<objective>
Re-scope the OSCE tab-scroll feature from the station axis to the sub-topic axis: opening a
station shows that station's sub-topics as swipeable tabs, instead of showing every station as
a tab.

Purpose: today `_OsceDetailScreen` builds one `Tab` per station, so tapping "Respiratory
System" drops the user into a 12-tab strip of unrelated stations and swiping sideways carries
them out of the station they chose. The user's correction is explicit — the tab scroll is for
the sub-topics within one topic. Each station already carries its sub-topic list
(`ResourceTopic.outline`, sourced from `scripts/content/OSCE.md`), and the one station with
real written content (Abdominal Examination) carries its sub-topics inside the content itself,
which is what "for Abdominal you can infer it" means.

Output: a pure, unit-tested derivation utility that turns a station (plus its loaded content,
when it has any) into an ordered sub-topic list, and an OSCE detail route rebuilt around it.
</objective>

    Write the failing tests first, then create `lib/utils/osce_subtopics.dart` exporting three
    things.

    First, an `OsceSubtopic` value class with a required `String title` and a nullable
    `Chapter content`; null content means this sub-topic has no written material yet.

    Second, a predicate `isOsceSubtopicHeading(String title)`. It strips a leading single-letter
    enumerator (one letter followed by a period and any spaces), then ignores every non-letter
    character. It returns true when the surviving letters are all uppercase, and also true when
    no letters survive at all, so a purely symbolic title starts its own group rather than being
    folded into the one above it. `A. INSPECTION`, `SPECIAL TESTS (HIGH-YIELD)`, `FBC` and `U&amp;E`
    are headings; `Light palpation` and `What is guarding?` are not.

    Third, `osceSubtopicsFor` taking a required `ResourceTopic topic` and an optional
    `Chapter? chapter`, returning an ordered list of `OsceSubtopic`. When the chapter is
    non-null and has at least one section holding at least one subsection: if it has more than
    one section, emit one sub-topic per section, titled by section title; otherwise walk that
    single section's subsections in order, opening a new group whenever the predicate says the
    title is a heading (and for the very first subsection regardless), and appending to the open
    group otherwise, then emit one sub-topic per group titled by the group's opening subsection.
    Each emitted sub-topic's content is a slice: a `Chapter` reusing the source chapter's id,
    title, order and chapterColor, with `tags` set to the empty list, holding a single
    `ChapterSection` that reuses the source section's id, title, order and color but carries only
    that group's subsections. Reusing the source chapter id keeps clip-note anchoring stable, and
    emptying tags stops the RELATED TOPICS chip block from repeating on every tab — document both
    reasons in dartdoc. When there is no usable chapter, emit one sub-topic per `topic.outline`
    entry with null content. When neither path produces anything, emit a single sub-topic titled
    with the station's title and null content.

    `test/utils/osce_subtopics_test.dart` (new directory), using package imports
    (`package:enchiridion/...`) and a single `void main()` like the rest of the suite.
